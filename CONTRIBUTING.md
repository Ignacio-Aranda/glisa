# Contributing

Thanks for helping! Bug reports with `glisa ctl probe` output from new devices are
especially valuable, and so are reports from Windows and macOS.

## Setup

You need:
- Rust (stable);
- Node.js 22;
- on Linux, the WebKitGTK development packages (see the README's *Building from source*).

```bash
cd app && npm ci
```
```bash
npx tauri dev -- -- --simulate
```

`--simulate` adds three simulated devices. The window alone also runs in a browser against a
mock of the service: `npm run dev`, then open http://localhost:1420/. Add `?mock=empty`,
`?platform=windows`, `?flow=pairing`… to see each state.

## Before opening a pull request

1. Run the checks:
   ```bash
   cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
   ```
   ```bash
   cd app && npm run check && npm test && node scripts/i18n.mjs check
   ```
   Windows code must at least type-check:
   ```bash
   cargo check --workspace --exclude glisa-app --target x86_64-pc-windows-gnu
   ```
2. Add tests for what you change:
   - device behaviour: the simulator in `crates/hidpp/src/sim.rs`;
   - Flow: two services on loopback (`crates/flow/tests/common`);
   - the window: vitest with the mock.
3. For visual changes, attach screenshots in **both themes** and **both languages**
   (`npm run screenshots` writes them to `app/screenshots-out/`).
4. Keep commits focused, with an imperative subject line in English.

## Rules

- Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) first: it defines the crates, the JSON
  API, events, and what each piece owns.
- The window talks to the backend only through `app/src/lib/backend.ts`. Colours, spacing and
  type come only from the design tokens (`app/src/lib/brand/tokens.css`,
  [docs/BRAND.md](docs/BRAND.md)).
- Platform code lives behind `cfg(target_os = …)`, small and isolated.
- No new runtime dependencies without discussion; prefer pure-Rust crates.
- No Logitech assets or data (images, icons, code, device databases). Original work only.

## Translations

Text in the code is English, always translatable, with named placeholders:
- Rust: `tr!`, `trn!`, `trc!`;
- the window: `t()`, `tn()`, `tc()`.

Translations are gettext files in `locale/<lang>/`, parsed at runtime:

| File | Contents |
|---|---|
| `core.po` | service and CLI |
| `flow.po` | Flow |
| `app.po` | tray, notifications |
| `buttons.po` | control and action names |
| `ui.po` | the window |

Commands:
- `node app/scripts/i18n.mjs check`: must pass.
- `node app/scripts/i18n.mjs missing`: lists what's missing.

To add a language:
1. Add it to `LANGUAGES` in `crates/i18n/src/lib.rs` and to the window's language list.
2. Create `locale/<lang>/`.
3. Run with `GLISA_LANG=<lang>`.
